# דף בדיקת מחזור משכנתא

יישום React, Tailwind CSS v4 ו־shadcn/ui. התוכן הציבורי מגיע מ־`config/landing/refi.json`; הזהות ומספר הטלפון נבחרים מתוך ההגדרות המאושרות של הפרויקט. אין ייבוא של מלוא הגדרות העסק לדפדפן.

## הפעלה ובנייה

מתיקיית הפרויקט הראשית, עם Node בגרסה 22.19 ומעלה:

```powershell
npm ci
npm ci --prefix apps/refi-landing
npm run dev --prefix apps/refi-landing
npm run build --prefix apps/refi-landing
```

הבנייה יוצרת `site/refi-cro`, כולל HTML מוכן מראש לדף הראשי ולנתיב `/thank-you`, פונטים מקומיים, נכסי המותג וקובצי כותרות אבטחה. תצורת nginx טוענת את `nginx-site.inc` המיוצר רק במארח הציבורי. הניתוב המדויק של הדף החדש ונתיב `/cro-assets/` נפרדים מדפי הפרטיות והשותפים ומנכסי `site/lp1v2`. נתיבי ה־API נשמרים; סביבת הבדיקה המוגנת ממשיכה לחסום קליטה. התקנה בשרת מחייבת משיכת הקוד, בדיקת nginx במכולה זמנית ואז יצירה מחדש של שירות `lp` בלבד.

שרת הפיתוח ותצוגת Vite אינם כוללים API. לתצוגה מקומית עם API מדומה בלבד:

```powershell
node apps/refi-landing/tests/server.cjs
```

הכתובת היא `http://127.0.0.1:4186`. אין לפרוס את שרת הבדיקה או את נתיבי `__test`.

## טופס ומדידה

הטופס שולח מיד אל `/api/lead` את חוזה הקליטה הקיים. ניסיון חוזר עם אותם פרטים משתמש באותו `event_id` ובאותו `idempotency_key`. שינוי פרטים יוצר אירוע חדש. מעבר לדף תודה מתבצע רק אחרי תשובת HTTP מוצלחת ואישור `request_id`; שגיאות, תשובת המתנה או JSON פגום אינם מוצגים כהצלחה. מניעת כפילויות בשרת נשארת באחריות שירות הקליטה הקיים.

להפעלת PostHog יש להעתיק את `.env.example` אל `.env.local` בתיקיית היישום ולהגדיר את מפתח הפרויקט הציבורי ואת כתובת השירות, ואז לבנות מחדש. אין להשתמש במפתח אישי או בסוד API. אירוע `quote_submitted` נשלח בנתיב `/thank-you` רק עם אישור קליטה והסכמת מדידה אופציונלית. אין שדות קשר, תשובות שאלון, כתובת דף מלאה או מפנה במטען המדידה. אין הקלטות מסך או אירועי שימוש אוטומטיים. סינון הבוטים נשאר פעיל. סימון מקומי מונע שליחה חוזרת באותה לשונית, ומזהה האירוע מועבר כ־UUID. הסימון מציין תור לשליחה, ואינו אישור קבלה מהשירות.

## סרטוני לקוחות

לא הומצאו סרטונים, חיסכון כספי או דירוגים. עד לקבלת סרטונים מאושרים מוצגות המלצות כתובות ותמונת לקוחות מהדף הקיים. להוספת וידאו יש להוסיף רשומה אל `testimonials.videos` בקובץ התוכן:

```json
{
  "approved": true,
  "title": "כותרת הסרטון",
  "name": "שם המפרסם המאושר",
  "src": "/testimonials/testimonial.mp4",
  "poster": "/testimonials/testimonial.webp",
  "captions": "/testimonials/testimonial.he.vtt",
  "source": "תיעוד מקור ואישור פרסום"
}
```

יש להניח את הקבצים המאושרים בתיקיית `public/testimonials` לפני הבנייה. כל רשומה מחייבת אישור מפורש, מקור, תמונת פתיחה וכתוביות. הסרטון נטען רק לבקשת המשתמש. שינוי מקורות חיצוניים מחייב התאמה של מדיניות האבטחה ובדיקת הרשאות מדיה.

## אימות

```powershell
npm run lint --prefix apps/refi-landing
npm test --prefix apps/refi-landing
npm run test:e2e --prefix apps/refi-landing
node apps/refi-landing/scripts/verify-negative.cjs
npm run audit --prefix apps/refi-landing
```

בדיקות הדפדפן משתמשות ב־Chromium ובספריית PostHog האמיתית, עם שרת קליטה ותעבורת מדידה מדומים. הבדיקה החיובית למדידה מגדירה מאפייני דפדפן רגיל לצורכי הבדיקה בלבד; בדיקה נפרדת מוכיחה שדפדפן אוטומטי עדיין מסונן. בדיקת הבקרה השלילית מסירה את בדיקת הצלחת HTTP מעותק זמני ומוודאת שהסוויטה נכשלת.

Lighthouse מריץ שלוש מדידות מובייל על הבנייה המקומית. נדרשת תוצאת LCP נמוכה מ־2.5 שניות בכל שלוש הריצות. זו מדידת מעבדה, ואינה מדידת משתמשים בשרת החי. מדידת זמן שיגור הטופס מוכיחה שהלקוח אינו ממתין לאנליטיקה; זמן המענה של nginx, n8n ו־Monday מחייב אימות נפרד בסביבה המיועדת.

הדוחות וצילומי המסך נשמרים תחת `tests/out/refi-cro-20261027`. דוח מוכנות למסירה נמצא ב־`docs/runtime/REFI_CRO_READINESS.md`.
