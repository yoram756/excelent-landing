# פריסת LP ובדיקת זמינות

יש לשמור ארכיון פרטי וסקריפט חזרה לגרסת Git קודמת לפני החלפת מכולה. גיבוי בהרשאות פרטיות נעשה בתהליך נפרד; `umask 077` לא נשאר במעטפת שמבצעת checkout. ב־checkout של קובצי אתר ציבוריים משתמשים ב־`umask 022`.

## בדיקת Nginx מבודדת

```sh
docker compose -f docker-compose.yml run --rm --no-deps --label traefik.enable=false lp nginx -t
```

`docker compose run` יורש את תצורת השירות. בשירות LP קיימות תוויות Traefik לאתר הציבורי. תווית הביטול ניתנת למכולת הבדיקה הזמנית בלבד, כדי שלא תפורסם כשרת אתר בזמן בדיקת התחביר. אין שינוי בתוויות המכולה הפעילה או בניתוב. [תיעוד Docker](https://docs.docker.com/reference/cli/docker/compose/run/) מפרט ירושת תצורה ואפשרות override לתוויות.

## החלפה ומוכנות

לאחר pull מסוג fast-forward לגרסה נעולה ובדיקת התחביר:

```sh
docker compose -f docker-compose.yml up -d --no-deps --force-recreate --pull never lp
docker exec lp-lp-1 nginx -t
python3 scripts/lp-release-readiness.py
```

בדיקת תחביר אינה הוכחת מוכנות של הפרוקסי. הסקריפט קורא רק נתיבי אתר ידועים, ללא POST. הוא משווה כל תשובה ציבורית לקובץ הפרוס, ומשווה בנפרד תשובה ישירה מתוך מכולת Nginx. נדרשות שתי תצפיות תקינות רצופות; לכל היותר שישה סבבים, עם timeout לכל בקשה. כל תצפית נשמרת, כולל 502 או חוסר התאמה. אין הפיכת 200 יחיד להוכחת הצלחה.

תשובה ציבורית שנכשלת לצד תוכן Nginx פנימי תקין מצביעה על בעיה במסלול הציבורי באותה תצפית. כשל בבדיקת הרכיב מסומן probe_unavailable; אין להסיק ממנו ש־Nginx עצמו מקולקל. היסטוריית שגיאה ללא לוגים אינה מוכיחה בדיעבד רכיב מסוים.

לאחר מוכנות בודקים את כל קובצי/נתיבי השחרור מול הגרסה הנעולה ואת הממשק החי. כשל חיוני שאינו נפתר בתוך מגבלת המוכנות מחייב חזרה לגרסה הקודמת ואימות זמינותה. אין לשנות ניתוב על סמך 404/502 בלבד.

בדיקות הסקריפט: `tests/deploy/lp_readiness_test.py`, ספרייה סטנדרטית בלבד. הן כוללות 200 ואחריו 502, כשל חלקי בין נתיבים, תוצאה ריקה ומגבלת ניסיונות. אין בהן פניות לשרת אמיתי. יש להשתמש ב־Python הקיים בסביבה, ללא התקנה אוטומטית.
