# חיבור TextMe לדוט

נוצר והותקן תוסף עבודה בדפדפן; המיומנות שלו מופעלת בחשבון. לא הוקם חיבור API ולא הופעל משלוח. לפי אישור מפורש של יורם הועברה לדוט בקשת בדיקה אחת. הדוט הגיע ל־TextMe ממחשב הענן, נתקל במסך כניסה והציג כפתור Open computer להשלמת הזדהות פרטית. חיבור הקריאה הפעיל עדיין BLOCKED עד התחברות בעל החשבון בסביבת הדוט.

התוסף: https://chatgpt.com/plugins/plugins_6ae261b29284819185d282ac2fc068d2

מזהה `plugins_6ae261b29284819185d282ac2fc068d2`, שחרור `pluginrel_6ae261b41d688191a00c609fe86025b2`, גרסה `0.1.0`, תוסף פרטי בהיקף USER. בקריאה חוזרת אומתו מיומנות אחת ואפס שרתי MCP. במסך Manage נצפה `Use excellent-textme-workflow = 1` וכפתור Uninstall.

## מה משמעות התוסף

מקור התוסף נמצא ב־`plugins/excellent-textme-management/`. הוא מכיל הנחיות עבודה מעשיות עם ממשק שכבר נבדק, ולא שרת MCP או חיבור API. אין בתוסף מפתח, Cookie, סיסמה או כתובת MCP שהומצאה. הדוט צריך גישה למחשב המחובר ולדפדפן המאומת, או התחברות נפרדת ובטוחה בדפדפן שלו. לא מעתיקים את סשן הדפדפן בין סביבות.

המיומנות מבדילה בין דוחות, תכנון, הרשאה לשליחה ומסירה בפועל. היא שומרת את שעות המשלוח ואת הגדרות החשבון, אוסרת קריאת ערכי טוקנים והפעלת קמפיין, ומגדירה את שלבי חיבור ה־API העתידי.

## פערי API והפעולה הבאה

לפי [תיעוד האימות הרשמי](https://docs.textme.co.il/guide/authentication/), טוקן תקף מאפשר כל פעולה שהחשבון מורשה לה. לכן אין לחבר טוקן כללי ישירות לסוכן תוך הבטחה טכנית של ״קריאה בלבד״. נדרש מתאם שמאפשר רק פעולות מוגדרות, מחזיק את הסוד במנגנון הקיים ומאמת את הדוט. אין צורך להניח שחייבים להנפיק טוקן שלישי; יש קודם לבדוק את ה־Credential הקיים ב־n8n בלי לחשוף ערך.

אותו תיעוד דורש בדיקת IP מורשה, אך המתג בחשבון כרגע כבוי. הפעלתו עשויה לשבש את n8n ואת משתמשי הטוקנים האחרים, ולכן דרושים מיפוי יציאות קיים ואישור לרשימת IP מדויקת לפני שינוי. מצב זה אינו מונע את קריאת דוחות הדפדפן שכבר אומתה.

התוסף מותקן ומופעל, אך המכשירים המקומיים אינם זמינים לדוט כרגע. לפי אישור יורם הועברה בקשת בדיקה ממחשב הענן. התוצאה בפועל: נדרשת התחברות נפרדת. בעל החשבון צריך לפתוח בשיחת ״העוזר של אקסלנט״ את Open computer, לבחור Take over ולהשלים כניסה פרטית ל־TextMe, ללא סיסמה בצ׳אט; לאחר מכן להחזיר שליטה לדוט. החלון נפתח על ידינו למסירה, עבר ממצב Connecting ל־Live computer, ומסך הכניסה של TextMe אומת גם חזותית. השליטה נשארה בידי הדוט; לא נלחץ Take over ולא הוזנו פרטי התחברות. צילום מסך הכניסה נשמר מקומית בלבד ב־`tests/out/textme-dot-20261028/dot-cloud-login.png`, מחוץ ל־Git. אין להעביר Cookies או לאפשר גישה רחבה יותר למחשב כדי להסתיר את הפער. חיבור אוטומטי נוסף דרך API יושלם לאחר הכנת המתאם והרשאותיו לאישור; אינו מוצג כאן כמוכן.

ראיית בקשת הכניסה נשמרה ב־`docs/evidence/20261028-textme-dot/dot-signin-required.txt`, ללא שיחות אחרות. לא נשלחה לדוט בקשה נוספת ולא הורחבה בדיקת הקריאה שאושרה.

בקשת ״חבר גם אותו לדוט״ אינה אישור להפעלת SMS או להרחבת שעות. ההסכמה הקודמת לדון בשליחה אוטומטית ב־Cosend אינה אישור לקמפיין TextMe. ההגדרה הקיימת ב־`config/lead-service.json` משאירה שליחת TextMe בהמתנה לאישור נפרד; לא שונתה.

במהלך הניווט, סקירת האישור האוטומטית דחתה לחיצה ראשונית משום שזיהתה אותה כלחיצה על צ׳אט תמיכה. לא נפתחה פנייה. בוצעה תצפית חדשה ואומת הכפתור בצילום; הבדיקה המשיכה בניווט רגיל לדוחות ולהגדרות. אין חסם הרשאה שנותר מפעולה זו, ולא נעשה ניסיון לפנות לתמיכה בעקיפין.
